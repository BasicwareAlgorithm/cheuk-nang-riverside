# 卓能河畔轩 CRM V2 详细设计

## 目标与原则

- 销售只能查看自己名下客户，管理员按角色获得管理和导出权限。
- 所有账号、客户归属、合并、批量操作和导出均保留审计记录。
- 高风险操作先预览、再确认；不自动覆盖账号、不按姓名自动合并客户。
- 列表全部改为服务端搜索、筛选和分页，避免一次加载全部数据。
- 销售可查看自己名下客户的完整手机号；管理员按角色决定查看和导出明文或脱敏手机号。

## 1. 销售账号生命周期

### 数据

在 `crm_sales_accounts` 增加：

- `must_change_password`：管理员重置密码后，销售下次登录必须修改。
- `disabled_at`、`disabled_reason`：停用时间与原因。
- `password_reset_at`：最近一次重置密码时间。
- `last_login_at`：最近登录时间。

`login_name` 继续存放登录手机号，新账号必须是唯一的 11 位大陆手机号。历史非手机号账号继续可用，后台标记为“历史登录名”，由管理员逐个补手机号。

### 操作

- 停用：立即禁止新登录；已有会话下一次请求失效；邀请码停止归属新客户；原客户与历史记录保留。
- 恢复：恢复登录和邀请码，不自动改变客户归属。
- 修改手机号：校验手机号格式与唯一性；修改后旧手机号立即不能登录。
- 重置密码：管理员设置临时密码；销售登录后必须修改；密码不在后台回显。
- 所有操作必须填写原因并写入审计表。

### API

- `PATCH /api/crm/admin/sales/:id/status`
- `PATCH /api/crm/admin/sales/:id/phone`
- `POST /api/crm/admin/sales/:id/reset-password`
- `POST /api/crm/change-password`

## 2. 完整跟进历史时间线

`crm_followups` 继续作为不可覆盖的事件表，每次保存产生一条新记录，不修改旧记录。

时间线内容：

- 跟进时间、销售、客户状态、备注。
- 下次跟进时间。
- 归属变更、客户合并等系统事件也显示在时间线上。

权限：销售只能读取当前归属客户的历史；管理员可读取全部。接口分页返回，每次 20 条。

- `GET /api/crm/leads/:id/followups?cursor=...`
- `GET /api/crm/admin/leads/:id/followups?cursor=...`

## 3. 下次跟进与到期提醒

在 `crm_customers` 增加：

- `next_followup_at`：当前下一次跟进时间。
- `reminder_state`：`pending`、`done`、`cancelled`。

保存跟进时可选下次跟进时间；保存后更新客户当前提醒。销售端提供：

- 已逾期。
- 今天待跟进。
- 未来 7 天。
- 暂无计划。

第一阶段只做 CRM 站内提醒和数量徽标，不发送短信、微信或邮件。后续若接企业微信/短信，需要单独配置服务商和通知模板。

## 4. 客户批量分配与批量导入

### 批量分配

- 客户列表增加复选框和“批量分配”。
- 必须选择目标销售并填写统一原因。
- 后端重新校验销售状态和客户 ID；用 D1 batch 执行。
- 返回成功、跳过、失败数量及逐行原因；写一条批次审计和每位客户的归属审计。

### CSV 导入

标准字段：`客户姓名`、`手机号`、`销售登录手机号`、`状态`、`备注`、`下次跟进时间`。

流程：

1. 浏览器选择 CSV。
2. 后端解析和校验，不直接写库。
3. 返回预览：可新增、手机号冲突、销售不存在、格式错误。
4. 管理员确认后执行。
5. 默认冲突策略为“跳过并报告”，不静默覆盖。

限制：单文件 1 MB、每批最多 500 行、UTF-8/Excel BOM 均支持。

## 5. 重复客户合并

不按姓名自动合并。自动候选仅基于标准化后的相同手机号；其他情况只能由管理员手动选择。

合并流程：

1. 选择主客户和待合并客户。
2. 预览姓名、手机号、归属、状态、咨询、跟进和提醒的处理结果。
3. 必须填写合并原因并二次确认。
4. 将咨询、跟进、归属审计指向主客户。
5. 待合并客户标记 `merged_into_customer_id`，不物理删除，便于追溯和恢复。
6. 冲突字段采用明确规则：最新姓名、管理员选择归属、最高意向状态、最早创建时间、最新待办提醒。

## 6. 服务端搜索与分页

销售账号和客户列表接口统一支持：

- `page_size`：默认 50，最大 100。
- `cursor`：基于排序字段和 ID，避免大数据量下 OFFSET 变慢。
- `q`：姓名或手机号搜索。
- `status`、`sales_id`、`active`、`reminder`：筛选。

响应结构：

```json
{
  "items": [],
  "next_cursor": null,
  "has_more": false,
  "total": 0
}
```

新增手机号、状态、归属、更新时间等索引。前端翻页时保留当前筛选条件。

## 7. 管理操作与 CSV 导出审计

扩展 `crm_audit_logs`：

- `request_id`：串联一次操作。
- `metadata_json`：记录筛选条件、批次 ID、影响数量，不存密码。
- `actor_admin_id`：具名管理员 ID。

审计事件包括：账号创建/停用/恢复/改手机号/重置密码、客户分配/批量分配/合并、CSV 导入、CSV 导出、查看明文手机号。

CSV 不再完全在浏览器生成，改由后端生成并记录导出人、导出时间、筛选条件、行数和是否包含明文手机号。

## 8. 手机号脱敏与导出权限

建议新增具名管理员表 `crm_admin_accounts`，角色：

- `super_admin`：账号管理、客户合并、明文查看与导出、审计查看。
- `operator`：客户分配、导入、跟进查看；手机号默认脱敏；不可导出明文。
- `viewer`：只读统计和脱敏列表；不可修改或导出。

销售端可查看自己名下客户的完整手机号。`operator` 和 `viewer` 管理员默认显示 `166****8306`；只有 `super_admin` 可以查看和导出完整手机号。导出明文手机号必须再次确认并写审计。

当前共享 `ADMIN_PASSWORD` 仅作为首次创建超级管理员的引导凭证；具名管理员建立后应停用共享密码登录。

## 数据迁移

新增 `0003_crm_operations.sql`：

- 新建 `crm_admin_accounts`、`crm_import_batches`。
- 扩展销售、客户、跟进和审计字段。
- 增加分页、提醒、手机号和归属索引。
- 不删除或重写现有客户、销售、跟进数据。

迁移先在本地 D1 验证，再执行远程迁移。生产迁移前导出 D1 备份，并记录恢复点。

## 实施顺序

1. 数据迁移、具名管理员与权限中间件。
2. 销售账号停用/恢复/改手机号/重置密码。
3. 服务端搜索、分页、脱敏与审计导出。
4. 跟进时间线、下次跟进和站内提醒。
5. 批量分配与 CSV 预览导入。
6. 客户合并与恢复机制。
7. 管理后台和销售端界面整合、移动端与压力测试。

## 验收

- 权限隔离、手机号脱敏、导出审计测试。
- 账号停用后会话立即失效测试。
- 批量导入幂等、冲突和部分失败测试。
- 合并前后关联记录、审计和恢复测试。
- 1 万客户规模的分页与搜索性能测试。
- D1 迁移、备份与回滚演练。
